# Repository workflow

Keep changes focused and use the simplest approach that solves the problem. Follow the user's scope
and run checks relevant to the change. See [CONTRIBUTING.md](CONTRIBUTING.md) for project commands.

## Pull requests

- Open a PR only when the user asks for one. Keep one request in one PR unless asked to split it.
- Use a clear title and a few sentences explaining the problem, the fix and how it was checked.
- Add detail or screenshots only when they help review. Skip exhaustive checklists and agent credits.

## Documentation

Update existing guidance when needed. Document useful decisions or non-obvious constraints; avoid
restating the code or recording a history of the work.
